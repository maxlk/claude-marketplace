Backlog.md for Claude Code

A kanban board that lives in your repository and that Claude keeps up to date. You choose where it's stored, which columns it has and which fields a task must have. The plugin holds Claude to those choices.

Claude CodeGitNode.js 18+Backlog.md 1.55.3+macOS or Linux

Install

  1. Install the Backlog.md command

    npm i -g backlog.md

  2. Add the plugin in Claude Code

    /plugin marketplace add maxlk/claude-marketplace
    /plugin install backlog-md@maxlk

  3. Start Claude Code in a project

    Claude offers to set up a board the first time. Choose Not now to be asked again in 14 days, or Never in this project. You can run /backlog-md:setup at any time.

How required fields work

Rules apply at three moments: when a task is created, when work starts on it, and when it's finished. Each moment rechecks the earlier ones. warn lets the change through and tells Claude what's missing. block writes nothing until it's fixed.

Rules to try

Drafts are exempt until they're promoted. Older tasks aren't checked until they move forward, so turning on rules for an existing board doesn't disrupt it. A milestone must already exist, because Backlog.md would otherwise accept a mistyped name without complaint.

What runs by itself

WhenWhat the plugin does
A session startsPoints Claude's backlog command at this project's board, restores the board if its checkout went missing, gets the latest version, and gives Claude a short summary of the board and rules.
Claude runs backlogChecks your required fields before anything is written. Retries if another agent is editing the same task. Simple board commands run without a permission prompt.

The session endsSaves the board and, if sync is on, pushes it.

Using the board from your own terminal

The automatic routing only exists inside Claude. If your board isn't in your code tree, ask Claude to run this and add the printed line to your shell profile:

backlog-md shell-init

It gives you a blg command. For a dedicated-ref board, it looks like this:

blg() { BACKLOG_CWD="$(git rev-parse --path-format=absolute --git-common-dir)/backlog-wt" backlog "$@"; }

Then use blg board or blg browser. To have Claude start the web board instead, run /backlog-md:status --web.

Working in a team

A teammate joins

When someone with the plugin opens a clone of the repository, Claude offers to attach the shared board. They don't choose presets, because the rules travel with the board.

Sync

Setup asks before turning on sync, and names the remote. The board branch is as visible as the repository. It never force-pushes.

Two people change the board

Changes to different tasks merge automatically. If the same task changed on both sides, sync pauses and your board stays as it is. Run /backlog-md:sync and Claude walks you through choosing a version.

Task numbers collide

Two people can create the same task number while offline, which stops the board listing tasks. The plugin tells you, and /backlog-md:doctor renumbers them with your agreement.

Limits you should know

  • Rules bind Claude, not people. Your terminal and the web board aren't gated. /backlog-md:doctor --audit lists tasks that slipped through.
  • Board commits skip your git hooks and commit signing, so they can't hang in the background. That includes any secret scanner in your hooks. If you need those on the board, choose a storage option you commit yourself.
  • Human approval is a guardrail, not a security boundary. The Agent-driven preset uses Claude Code's permission prompt, which permissive modes skip.
  • Status-change scripts are refused until you trust them. A Backlog.md board can run shell commands when a task moves, and a pulled board could contain one.
  • Moving a board between storage options is manual. The README lists the steps.
  • Claude Code only. The plugin relies on features that claude.ai and Cowork don't load.

Troubleshooting

Start with /backlog-md:doctor, which checks all of this and suggests fixes.
